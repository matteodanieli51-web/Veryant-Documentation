#### DatabaseBridge

The follwing tips are applicable when working on databases with isCOBOL DatabaseBridge.

- If the database service runs on a separate machine than the isCOBOL Runtime, the network speed and latency might affect performance.
- Handling locks through the Application Server or through the File Server by setting [iscobol.file.lock_manager \*](../../../../SDK-Users-Guide/Compiler-and-Runtime/Configuration/Configuration-Properties#file_lockmanager) to "com.iscobol.as.locking.InternalLockManager" is faster than having locks handled by the database engine. As side effect, the concurrency is managed only between clients connected to the same isCOBOL Server, so this tip is not applicable if you’re working on the database with other tools in addition to the COBOL application. In addition, using a lock manager is not suggested when there are a lot of clients connected simultaneously (e.g. more than 100 clients) as it decreases performance in this case.
- EDBI routines check for table existence with a SQL query on database catalogues every time a OPEN is performed. If your application includes several OPEN statements and you’re sure that tables exist on the database, you can avoid this check by generating EDBI routines with [iscobol.compiler.easydb.no_check (boolean)](../../../../SDK-Users-Guide/Compiler-and-Runtime/Configuration/Configuration-Properties#compiler_easydb_no_check) set to true. Use the [-nocheck](../../../../../is-cobol-db-bridge/DatabaseBridge-generator-edbiis#nocheck) edbiis option if you’re using the two-steps legacy approach.
- When you generate subroutines for Oracle, set [iscobol.compiler.easydb.oracle.hints](../../../../SDK-Users-Guide/Compiler-and-Runtime/Configuration/Configuration-Properties#compiler_easydb_oracle_hints) to 2 in order to obtain better performance for START on alternate keys on huge tables. Use the [-oho](../../../../../is-cobol-db-bridge/DatabaseBridge-generator-edbiis#oho) edbiis option if you’re using the two-steps legacy approach.
- When you generate subroutines for MySQL, set [iscobol.compiler.easydb.mysql.hints (boolean)](../../../../SDK-Users-Guide/Compiler-and-Runtime/Configuration/Configuration-Properties#compiler_easydb_mysql_hints) to true in order to obtain better performance for START on alternate keys on huge tables. Use the [-mh](../../../../../is-cobol-db-bridge/DatabaseBridge-generator-edbiis#mh) edbiis option if you’re using the two-steps legacy approach.
- When you generate subroutines for MySQL, Postgres or Microsoft SQL Server, set [iscobol.compiler.easydb.light_cursors](../../../../SDK-Users-Guide/Compiler-and-Runtime/Configuration/Configuration-Properties#compiler_easydb_light_cursors) to 2 in order to optimize the use of SQL cursors for read operations. Use the equivalent [-dmld](../../../../../is-cobol-db-bridge/DatabaseBridge-generator-edbiis#dmld), [-dpld](../../../../../is-cobol-db-bridge/DatabaseBridge-generator-edbiis#dpld) and [-dsld](../../../../../is-cobol-db-bridge/DatabaseBridge-generator-edbiis#dsld) edbiis options if you’re using the two-steps legacy approach.
- You can reduce the number of processed records by setting [The EDBI-WHERE-CONSTRAINT external variable](../../../../../is-cobol-db-bridge/Runtime-Options-and-Configuration/The-EDBI-WHERE-CONSTRAINT-external-variable).
- If the key you use for the START has a lot of segments, but you need to use only the first few of them, you can use the SIZE clause to limit the size of the key to the size of the useful segments only. This will reduce the number of SELECT queries generated by isCOBOL DatabaseBridge to simulate the START. **Note** - when using the two-steps legacy approach to generate EDBI routines, the [-sl](../../../../../is-cobol-db-bridge/DatabaseBridge-generator-edbiis#sl) option must be used in order to activate the support for START WITH SIZE.
- The performance of the START operation can be improved by setting [iscobol.easydb.limit_dropdown](../../../../SDK-Users-Guide/Compiler-and-Runtime/Configuration/Configuration-Properties#easydb_limit_dropdown).
- For multi-record files, where you have a table for each record definition, you can tell the START statement to use one specific table depending on the record type instead of using all the tables related to the multi-record file. To achieve it, set [iscobol.easydb.start_on_specific_table (boolean)](../../../../SDK-Users-Guide/Compiler-and-Runtime/Configuration/Configuration-Properties#easydb_start_on_specific_table) to true in the configuration and ensure that the record type field is properly set before the START statement.
- ESQL (SQL logic) is preferable to the COBOL code generated by isCOBOL DatabaseBridge (COBOL logic) when you need to perform
  - huge update operations (one single complex query is usually faster than multiple small queries generated by multiple REWRITE statements)
  - complex searches (filters in the WHERE condition of SELECT are preferable to reading all records and performing checks with COBOL statements).
  - testing of few fields (specifying the fields you wish to test in SELECT is preferable to reading the whole record including the fields you’re not interested in)
- DatabaseBridge performance is affected also by the JDBC configuration. See [Driver configuration](./JDBC-ESQL#driver-configuration) for more advice.
